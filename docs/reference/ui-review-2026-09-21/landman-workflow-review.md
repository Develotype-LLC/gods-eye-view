# LANDMAN workflow review

Read-only source review, 2026-09-21. No browser observation, edits, deployments, or private records inspected. Priorities below are UX proposals for selection, not implementation commitments. Effort S=contained UI change, M=several connected surfaces, L=data/state/API work.

## Top five recommendations

1. **P1 · Separate route setup from route comparison (high impact, M).** Current LONG-Haul is a single long form: endpoints plus optional geometry, five numerical crossing preferences, operating scenario, ranking slider, draft controls, then results and detail (`src/reference/pipelinePlanner.js:48-54`). Move to Setup → Compare → Land review, with persistent route name/endpoint summary and an Edit setup action. Keep presets as the default; move equivalent-km penalties behind Advanced routing preferences. Comparison should become the primary visible content when complete, rather than living below all inputs. Preserve existing caveats beside relevant metrics, not as lengthy repeated preambles.
2. **P1 · Make owner relationships a actionable worklist (high impact, M/L).** Directory currently renders up to 200 recent records as text buttons with raw codes, relationship, one transaction/willingness and follow-up (`src/reference/ownerWorkspace.js:300-329`). Provide filters for unresolved parcels, follow-up due, assigned person, relationship and proposal; present human labels and sortable columns/cards. Route owner lists should show concise relationship/next-action summaries in the chosen project (`src/reference/pipelinePlanner.js:758-811`), with a batch research queue rather than opening every owner to discover whether anyone knows them. Scope queries to project membership; do not expose private annotations via public exports.
3. **P1 · Clarify what the ownership slider actually does (high impact, S).** “Balance: owner-name priority” appears before Find route alternatives (`src/reference/pipelinePlanner.js:52`), but it only ranks generated candidates, and the disclaimer explaining that is farther below (`:576`, `:904`). Relocate it to comparison and label “Rank these alternatives: pumping ↔ recorded owner names”. Show independent known names, affected parcels, unresolved parcels and unmapped length. Existing separate counts are good; preserve the overlap of partially unresolved parcels with known-owner parcels. Add plain definitions to column headers rather than imply contracts or optimized acquisition cost.
4. **P2 · Make layer inspection non-disruptive (high impact, S/M).** Clicking a layer name currently enables it, opens its inspector and flies the camera (`src/reference/landmanWorkspace.js:195-204`). View presets turn off all non-preset layers and fly to fixed bounds (`:242-263`). Separate toggle, Details, and Zoom to coverage. Preserve camera by default when changing topic/layer, and explicitly label Replace visible layers for curated views. Otherwise a user researching a chosen parcel can lose context simply by asking about a source. Validate with live walkthrough before finalizing interaction.
5. **P2 · Split owner profile into summary and edit sections (medium/high impact, M).** Fourteen editable fields, parcel list and action buttons are rendered together (`src/reference/ownerWorkspace.js:51-65`, `:72`). Default summary: relationship, selected transaction assessment, confidence/date, next action, parcels. Tabs/sections: Parcels · Relationship · Proposal · History; explicit Edit with sticky Save/Discard. Transaction switching currently refuses while dirty and sets dirty just on selection (`:337-356`): separate selecting a saved assessment from editing it. Retain conflict protection and prevent accidental navigation loss.

## Additional opportunities

- **P2 · Task navigation vs reference catalog (M).** Sidebar contains five thematic views, three substantial tools, API-only well search, layer search, 16 grouped layers, RRC archive and source library (`src/reference/landmanWorkspace.js:60-69`; `src/reference/landmanModel.js:16-213`). Consider top-level Explore / Plan pipeline / Owners & research, with layers as a contextual drawer. Land ownership lacks a curated task view despite being central to this user; add Land & owners. Add Palo Duro region shortcut alongside Permian/Texas/US (`landmanWorkspace.js:60`, `:342`). Keep Full console secondary.
- **P2 · Helpful project access state (S).** No-project state throws “No relationship project is assigned to your login” after mounting an active-looking editor/search surface (`ownerWorkspace.js:139-147`). Show a concise access explanation and public parcel exploration action; preserve private project creation where authorized. Do not solve UX by granting membership automatically.
- **P2 · Visible evidence availability (S/M).** Interest dropdown offers documented mineral/leasehold/easement/etc despite actual import coverage potentially empty (`src/reference/land.js:508`). Present per-interest coverage counts and “No imported evidence” before running an empty query. Appraisal names and name-match classes should remain explicitly unverified. Live data counts were not inspected.
- **P2 · Better study persistence (L).** Save draft here is a single browser-local draft and export is GeoJSON (`pipelinePlanner.js:53`, `:935`). Users working with Dia/Antony need named studies, timestamp/status, chosen candidate and explicit sharing. Separate shared route study from private owner annotations. This is state/API work, not just button wording.
- **P3 · Actionable crossing review (S/M).** Mapped crossings are plain type/name/coordinates paragraphs (`pipelinePlanner.js:695-707`). Make each selectable: highlight on map, show source, add review status/note, return to candidate. Same pattern can serve terrain high points and unknown-owner parcels.
- **P3 · Dense results on narrow panels (M).** Seven-column candidate table scrolls horizontally (`pipelinePlanner.js:592`; `src/ui/styles/landman-workspace.css:975`). Candidate cards with aligned key metrics may serve tablet widths; use a wider comparison tray on desktop. Browser verification needed for actual clipping and map space.

## Keep

- Operating presets with optional custom detail.
- Distinct known names/parcels/unresolved and explicit incomplete-coverage behavior.
- Source dates, unknown vs zero, preliminary status.
- Return-to-route behavior, map highlighting, project-scoped private records, dirty/conflict safeguards.

## Suggested review session

Ask Brian/Dia to walk through: choose a basin → inspect ownership → find a known contact → make and compare a corridor → identify research obligations → save/share a study. For each, note clicks, unexpected map movement, scroll depth, unclear terminology, and whether the next action is visible. Select first release scope from top five before implementation. No assumption that more panels or more color alone fixes workflow.
